# Unresolved Items & Engineering Assumptions

## 1. 待验证与留待后续审核事项 (Items Needing Review)

1. **SimBoosts 加速寻客端点兼容性 (`/api/v1/rush/:token/`)**：
   * **现象**：在官方包中，销售办公室与猎头寻访共享了 `rush` 逻辑，部分调用处传入的是 UUID 令牌，部分则直接使用数值 ID。
   * **建议**：Phantom 后端需支持两种格式的宽容入参。

2. **餐厅星级变化多并发计算 (`ratingDelta`)**：
   * **现象**：当同一玩家拥有多家餐厅并发结算营业班次时，星级评分的衰减与提升依赖于前置轮次的服务表现。
   * **建议**：在后续压力测试中补充并发单元测试覆盖。

3. **季节性集市在淡季的客户端表现**：
   * **现象**：在淡季（饱和度低于 0.8 时），官方包中建筑占位格仍可能保留，但无法追加销售任务。
   * **建议**：在 DOM E2E 跑测中对淡季进行状态模拟。

## 2. 工程假设 (Engineering Assumptions)

* **SPA 路由假设**：所有前端页面跳转均走客户端路由，API 调用统一经过带 CSRF 与 Yep 握手的通用客户端封装。
* **数据权威假设**：静态游戏常数与配方（`resources.json`, `buildings.json`）以解包提取的数据为单一权威事实，无需服务端在每次请求中重复下发物料全量属性。

## 3. 下一步工作建议 (Next Steps)

1. **E2E 行为闭环验证**：使用 Playwright 启动前端并登录测试企业，验证零售大楼排产、销售办公室接单交付、以及百科全书成本测算的实时反馈。
2. **现代前端切片对接**：将 `restored/` 目录中的语义代码整合为新一代轻量化 React 组件库的基础构件。
